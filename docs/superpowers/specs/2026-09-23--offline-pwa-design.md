# W3 — Offline PWA: Installable Shell & an Honest "Server Unreachable" State — Design

- **Status:** awaiting user review (design gate) — no implementation yet
- **Classification:** **Architectural** (new served routes, a service worker, new binary assets, a new client state machine, packaging + CSP implications)
- **Date:** 2026-09-23
- **Decisions locked with the user:** scope **A** (installable + shell survives the server being down, *no content caching*), offline UX **banner + disable what cannot work**, icons **SVG source + generated 192/512 PNGs** (pure-Python generator, no new dependencies)
- **Branch:** `arena/01a0cd46-machinelearningmachine` (W1 presets → W2 theme → W4 copy prompt all shipped; this is the last of the four)

---

## 1. Context & Problem

The dashboard is a **thin client to a local server that owns everything**: agents, provider keys, the run queue, the mesh itself, and the saved transcripts (server-side, per-tab). The static shell is served *by that same process*.

Two user-visible consequences today:

1. **The browser's error page is the offline story.** If the server is not running — the commonest reason being "I closed the terminal / the launcher window" — opening `http://127.0.0.1:8000` gives `ERR_CONNECTION_REFUSED`. Nothing about the dashboard survives: not the layout, not the theme, not the explanation of what to do.
2. **It is not installable.** No manifest, no icon files (`/favicon.ico` 404s; the tab icon is an inline `data:image/svg+xml` ⚡). "It's an app I can pin" is not available.

What offline **cannot** mean here, and must not be implied: running dialogues. With the server down there is no mesh, no provider, no Python. Scope A therefore caches **the shell only** — never API responses, never transcripts. Nothing rendered offline can be stale *content*, because no content is shown offline.

### 1.1 Recon facts this design depends on (verified, not assumed)

| Fact | Evidence |
| --- | --- |
| Service workers need a **secure context** | `http://127.0.0.1:*` and `http://localhost:*` qualify; a LAN `http://192.168.x.y:8000` **does not**. All three launchers open `http://127.0.0.1:$PORT`. A LAN user gets no service worker at all — the feature must degrade silently, not error. |
| The **CSP already allows** a same-origin worker | `script-src 'self'`; `worker-src` falls back child-src → script-src. `manifest-src` falls back to `default-src 'self'`. **No security-header change is needed** — and none is allowed by this spec. |
| No `Cache-Control`, no hashed filenames, no asset build step | The shell files are edited in place; ETags come from Starlette. A cache-first worker would serve stale `app.js` during development. |
| `"/"` is a **route**, not static | `@app.api_route("/")` → `FileResponse(STATIC_DIR / "index.html")`. So `/sw.js` and `/manifest.webmanifest` belong as root routes beside it — a worker served from `/static/` would be scoped to `/static/` and could not control the page. |
| `PUBLIC_PATHS = {"/", "/health", "/favicon.ico"}` | Served without a token check. `/sw.js` + `/manifest.webmanifest` + the icons must join this set, or install breaks the moment `--auth-token` is used. `/favicon.ico` is listed but **nothing serves it** → 404 today. |
| The client already has a connection lifecycle | `connectionStatus` pill: *Live Mesh Connected* / *Session released* / *Reconnecting…* / *Disconnected - Refresh to retry*, driven by socket events with backoff. No `online`/`offline` listeners exist. |
| Boot keeps failing silently | `/api/auth/status` → `/api/status`, both `.catch(() => {})`. Nothing marks the page as "server unreachable". |
| Wheel packaging is test-pinned | `tests/test_packaging.py` names required static files; the docs test pins README trees/counts. |

## 2. Locked Decisions (from the design dialogue)

1. **Scope A** — installable + shell survives the server being down. No cached transcripts, no cached API responses, no offline runs (impossible by construction).
2. **Offline UX** — the dashboard stays visible, a banner explains it, controls that need the server are disabled with a reason, local controls keep working, and recovery is automatic without a reload (and without losing text in the prompt box).
3. **Icons** — a hand-authored SVG lightning bolt matching the header mark (indigo→purple→pink rounded square), plus committed 192px and 512px PNGs generated by a dependency-free Python script, with a test that regeneration is byte-identical. `/favicon.ico` starts being served from a real file.

## 3. Approaches Considered

| Approach | Verdict |
| --- | --- |
| **A. Precache shell, explicit file list, network-first with cache fallback** | **Chosen.** Offline works; online behaviour is bit-identical to today (no staleness during development); the file list is drift-locked against the shipped assets. |
| B. Cache-first with a version token in the cache name | Rejected: with no hashed filenames and no build step, "version" would be a hand-maintained string that goes stale exactly when a developer edits `app.js` — the classic "why is my fix not there" footgun, in a repo whose whole point is that the tests tell the truth. |
| C. Cache-first for the shell, network-first for nothing, no drift lock | Rejected: same staleness, plus silent drift when a file is added. |
| D. No service worker (manifest + icons only) | Rejected by the user's scope choice: an installed app that still shows `ERR_CONNECTION_REFUSED` fails the actual user problem. |
| E. Full offline with cached transcripts | Explicitly out of scope (user chose A). Recorded here so the decision is not silently reversed later. |

### 4.2 Service worker design (`static/sw.js`)

- **Size, measured:** the shell that ships today is **14 files / 717 KB** by this rule (verified against the tree, exclusions applied); P1 adds the manifest, three PNGs and `favicon.ico`. That is the whole precache — cheap, and every byte of it already origin-local.
- **Cache name:** `mlm-shell-v1` — a static string. It changes only when the shell's *shape* changes (the file list lives inside `sw.js`, and browsers revalidate a worker script on navigation, so a changed list produces a changed script → reinstall → new cache → old ones deleted in `activate`).
- **Precache list:** exactly the shell — `index.html`, `style.css`, `app.js`, `theme.js`, `presets.js`, `markdown.js`, `vendor/tailwind.css`, `vendor/fontawesome/css/all.min.css`, the two `webfonts/*.woff2`, `vendor/marked/marked.min.js`, `vendor/dompurify/purify.min.js`, `vendor/highlight.js/highlight.min.js`, `vendor/highlight.js/styles/atom-one-dark.min.css`, `manifest.webmanifest`, the icons, `favicon.ico`. **Drift-locked** by test against the files actually shipped (§7.2). Three explicit exclusions, each for a reason: `vendor/licenses/*.txt` (legal text, never fetched by the page), `vendor/MANIFEST.json` (build metadata), and `sw.js` itself (browser-managed; a worker that precaches itself is an update-loop classic).
- **Fetch strategy:** **network-first, cache-fallback**, and only for same-origin `GET`s of shell assets. Precisely:
  - `request.method !== "GET"` → untouched (pass through).
  - URL starts with `/api/` or is `/ws` → **never touched, never cached** (the scope-A promise: no content in the cache).
  - Navigation requests (`mode === "navigate"`) → network; on failure, `caches.match("/")` and serve the cached shell.
  - Everything else same-origin GET → network; on failure, cache; if not in cache, a plain failure (no invented responses).
  - **No artificial timeout on the network attempt.** A slow-but-alive server must win over a cached copy; serving the shell from cache while the real server is answering is precisely the staleness this design exists to avoid.
- **install:** `cache.addAll(precache)` with `{cache: "reload"}`; `skipWaiting()`.
- **activate:** delete every cache whose name is not the current one; `clients.claim()`.
- **No** `push`, `sync`, `periodicsync`, or fetch interception of anything outside the list. No third-party origins exist to worry about (`default-src 'self'` already forbids them).
- **Registration** (in `app.js`): only when `"serviceWorker" in navigator` **and** the page is in a secure context — i.e. registration is *attempted* and failure is swallowed with a debug-level log. On a LAN `http://` address there is simply no worker; the dashboard behaves exactly as today.
- **Update path:** after a new worker activates, the next navigation gets fresh assets (network-first). No "reload to update" prompt: with network-first there is no stale state to prompt about.
- **Limitation, stated rather than hidden: the origin includes the port.** A worker (and the shell cache, and `localStorage` for theme/presets) belongs to `http://127.0.0.1:8000`; if the next launch picks `:8001` because 8000 was taken, that is a *different origin* with no cache and no remembered theme. The docs will say "offline works for the address you used", and the launchers' first-free-port behaviour is the reason.

### 4.3 The "server unreachable" state machine (`app.js`)

The signal is **not** `navigator.onLine` — a local server can be down while the browser is happily online. The honest signal is *"the server is not answering"*:

| State | Entered when | UI |
| --- | --- | --- |
| `reachable` | boot probes succeed, or a later probe/socket open succeeds | today's UI; banner hidden; `data-requires-server` controls enabled |
| `unreachable` | boot probe fails on the network (not a 4xx), **or** the socket reports a non-released disconnect | banner shown; server-bound controls disabled; local controls untouched; prompt box content preserved |
| (existing) `released` | the server says the session was reaped | unchanged — the existing "Session released" pill stays authoritative; it is *not* "unreachable" |

- **Probe:** `GET /api/status` (public path, cheap). While unreachable: retry with backoff (1s → 2s → 5s → 10s, capped). The probe owns the unreachability verdict; the socket keeps its own existing reconnect backoff untouched, so the two never multiply each other's timers. On the first success: clear the banner, re-enable, call the existing `refreshMeshState()` and reconnect the socket — **no reload**, no lost text.
- **Banner:** a new element (`#offlineBanner`), not `#modeBanner`, because `#modeBanner` carries provider/simulation truth that must not be overwritten. Wording names the fix: *"The dashboard is open, but its server isn't running. Start it with the launcher — this page reconnects by itself."* It is `role="status"`, not an alert: it is not an error, and it must not steal focus.
- **Disabled controls** (marked in markup with `data-requires-server`, so the set is data-driven and testable rather than a hand-maintained id list in JS): `#btnRun`, `#btnStop`, `#btnNewAgent`, the Add Module modal's Register, `#btnSaveSession`, `#btnSessions` (its rows come from the server), `#btnReadUrl`, provider verify/save, `#btnClear` (it clears server state), and the dynamically-built session-row buttons. **Not** disabled (all local): theme toggle, copy prompt, prompt box, presets (built-ins, save, rename, delete, export/import), TTS/dictation, help, search.
- **Tooltip/aria:** each disabled control gets `title` + `aria-describedby` pointing at the banner, and the disabled state is conveyed by `disabled` (not colour alone).

## 5. Security, Packaging & Invariants

1. **CSP is unchanged.** No new directive, no relaxation. Verified by an existing test that pins the header (`tests/` security suite) — this spec requires *no* exception, which is the point of vendoring.
2. **`PUBLIC_PATHS` grows by exactly two entries** (`/sw.js`, `/manifest.webmanifest`). `/favicon.ico` is already there. Nothing else becomes unauthenticated — in particular `/api/*` is untouched.
3. **`/sw.js` must be served `Cache-Control: no-cache`** (browsers special-case workers, but being explicit avoids an update-loop question) and with `Content-Type: text/javascript`. `manifest.webmanifest` → `application/manifest+json`.
4. **No dependency changes.** PNG generation uses `zlib` + `struct` from the stdlib. No npm addition, no Tailwind rebuild, no new vendor asset.
5. **Wheel packaging** must keep shipping the new files (`tests/test_packaging.py` list extended) — an installed wheel that lacks its icons/shell is exactly the silent failure that test exists for.
6. **The offline banner must be light/dark correct**: it adds markup with colour utilities, so the W2 drift locks apply and the light layer must cover them.
7. **No inline scripts/styles**: the worker registration lives in `app.js`; the manifest is a file. (`tests/test_frontend_security.py` enforces this.)

## 6. UI/UX Flow

1. **First visit, server up, localhost** — page loads exactly as today, worker installs in the background, precache fills. No visible change, no prompt, nothing to dismiss.
2. **Install** — the browser's own install affordance becomes available (Chrome/Edge: install icon in the omnibox; iOS Safari: Add to Home Screen with the PNG icon). Launching it opens the dashboard in a standalone window.
3. **Server down, app opened** (installed or in a tab) — the cached shell renders, the theme preference applies, and the offline banner appears with the fix spelled out. Server-bound controls are disabled; the user can still read the page, copy a prompt, adjust presets, switch theme.
4. **Server started again** — the probe succeeds, the banner disappears, controls re-enable, the socket connects, the roster and transcript arrive: the page is live again with no reload and no lost input.
5. **LAN address (plain `http://192.168.x.y`)** — secure context is unavailable, so no worker: the page behaves exactly as today, and the docs say so instead of overclaiming.
6. **`--auth-token` set** — the shell is public (`"/"` is in `PUBLIC_PATHS`), so it still renders offline and the banner appears; the token prompt only appears when the server answers, as today.

## 7. Testing

### 7.1 Client state machine — `tests/js/offline.test.mjs` (new, jsdom, `client-lifecycle` harness style)
- Boot with a fetch double that rejects → banner visible, `data-requires-server` controls disabled, local controls enabled.
- Boot with a fetch double that succeeds → no banner, nothing disabled.
- Unreachable → reachable: advance the probe clock, assert banner clears, controls re-enable, `refreshMeshState` ran, **prompt box text preserved**, and no page reload was simulated.
- A 4xx from a *reachable* server does **not** produce the offline state (it is not "unreachable").
- Socket-driven transition: a normal disconnect enters `unreachable`, a `session_released` frame does **not** (existing released state stays authoritative).
- The banner is `role="status"`, not focus-stealing, and names the launcher.

### 7.2 Service worker contract — `tests/js/service-worker.test.mjs` (new, no jsdom needed)
- The precache list **equals** the shipped shell file set minus the explicit exclusion list (drift lock, mirroring the repo's presets/theme locks).
- `install` caches the list with `cache: "reload"`; `activate` deletes non-current caches; the cache name is versioned.
- The fetch handler: ignores non-GET, ignores `/api/` and `/ws`, is network-first for shell assets, and falls back to `caches.match("/")` for navigations.
- **Negative lock:** `sw.js` must not contain `cache.put` outside install, must not reference `/api/`, and must not add a second cache name.

### 7.3 Server + assets — `tests/test_pwa.py` (new, pytest)
- `GET /sw.js` → 200, `text/javascript`, `Cache-Control: no-cache`; scope is root (no `Service-Worker-Allowed` needed).
- `GET /manifest.webmanifest` → 200, `application/manifest+json`, valid JSON with the required fields, `start_url: "/"`, `display: standalone`.
- Manifest icon sizes **match the real PNG dimensions** (parsed from the IHDR chunk, no Pillow).
- `GET /favicon.ico` → 200 (the dangling `PUBLIC_PATHS` entry is now honest).
- `/sw.js` + `/manifest.webmanifest` are reachable **with `--auth-token` set** (public-path regression test).
- `scripts/make_icons.py` regeneration is **byte-identical** to the committed PNGs (the drift lock that makes committing binaries defensible).
- The CSP header is unchanged (byte-for-byte).

### 7.4 Docs honesty + whole suites
- `tests/test_docs_are_accurate.py` extended for the new static files, counts, and the reworded offline claim.
- `tests/test_packaging.py` extended with the new required assets.
- Full sweep: pytest (all), `npm run test:js`, ruff, `npm run audit:js`, e2e, vendor-tree byte-identical, no dependency changes.

## 9. Success Criteria & Traceability

1. **Installable**: launching from `http://127.0.0.1:PORT` offers install (Chrome/Edge) with a real 192/512 icon; iOS Add to Home Screen shows the PNG icon. *(P1)*
2. **Survives the server being down**: with the server stopped, opening the dashboard shows the dashboard — banner, disabled server-bound controls, working local controls — instead of `ERR_CONNECTION_REFUSED`. *(P2+P3)*
3. **Auto-recovers**: starting the server clears the banner and re-enables everything with no reload and no lost prompt text. *(P3)*
4. **No content is ever cached**: no API response, transcript or session data enters the cache; a test proves `/api/` never reaches the cache. *(P2)*
5. **Nothing overclaims**: docs state the secure-context limit (no worker over a plain LAN `http://` address), and the reworded "offline" claim distinguishes *no third-party assets* from *the PWA offline story*. *(P4)*
6. **Zero collateral**: CSP byte-identical, no new dependencies, dark mode untouched, light mode covered by the existing drift locks, whole suites green. *(every phase)*

## 10. Feature-Level Non-Goals (reasoned)

1. **Cached transcripts / offline reading** — user chose scope A; would put user content in a browser cache on disk and needs a staleness banner of its own.
2. **Background sync, push, periodic refresh** — there is nothing to sync to: the mesh lives in a server process that is, by definition, not running.
3. **A "new version available — reload" prompt** — with network-first there is no stale shell to reload away from; adding the prompt would be pure noise.
4. **TLS/HTTPS support for LAN use** — a real feature (certificates, operator UX) that is out of scope here; the docs will state the limit instead of pretending it does not exist.
5. **Offline queueing of runs** ("run this when the server is back") — the server holds the run queue; a client-side queue would silently duplicate it.
6. **Making the *server* into a PWA/daemon that survives the shell closing** — different problem (process management), out of scope.
7. **Icon theming (maskable/monochrome variants)** — one good icon per size; maskable variants are a refinement with no user-visible gap at this stage.
8. **Legacy iOS meta tags** (`apple-mobile-web-app-capable`, status-bar style) — iOS 16.4+ honours the manifest's `display: "standalone"`; carrying obsolete meta tags for older iOS is not worth the markup. The `apple-touch-icon` link *is* included, because home-screen icons still come from it.
